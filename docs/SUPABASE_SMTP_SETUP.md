# Supabase Auth Custom SMTP Configuration & Bilingual Templates
**Nirai (நிறை) — Traditional Handloom E-Commerce Platform**

> [!CAUTION]
> **LAUNCH BLOCKER:** The default Supabase Auth email service is strictly rate-limited to approximately **3 to 4 emails per hour**. In a production environment, customers registering or resetting passwords will experience delivery failures and lockouts. You **MUST** configure custom SMTP (e.g., Resend SMTP) and complete domain DNS verification before public launch.

## 1. Resend SMTP Configuration Guide

### Step 1: Obtain Resend SMTP Credentials
1. Log in to [Resend Dashboard](https://resend.com/).
2. Navigate to **API Keys** and generate a new API key with sending permissions (e.g. `re_...`).
3. Note your credentials:
   - **SMTP Host**: `smtp.resend.com`
   - **Port**: `465` (SSL) or `587` (TLS)
   - **User**: `resend`
   - **Password**: `<YOUR_RESEND_API_KEY>`

### Step 2: Configure in Supabase Dashboard
1. Open the [Supabase Dashboard](https://supabase.com/dashboard) and select your project (`lqzrahjmgzdsbosywjju`).
2. Go to **Project Settings** > **Authentication** > scroll to **SMTP Settings**.
3. Toggle **Enable Custom SMTP** to **ON**.
4. Fill in the fields:
   - **Sender email**: `orders@nirai.in` (Must match your verified domain)
   - **Sender name**: `Nirai Handlooms | நிறை`
   - **Host**: `smtp.resend.com`
   - **Port number**: `465` (or `587`)
   - **Minimum interval between emails**: `60` seconds (default)
   - **User**: `resend`
   - **Password**: `re_...` (Your Resend API key)
5. Click **Save Changes**.

## 2. Resend Domain Verification (SPF / DKIM / DMARC)

Without domain verification, Resend operates in **Sandbox Mode** and will **only deliver emails to the account owner's own email address**. Real customer notifications will fail with a `403 Forbidden` error.

Add the following DNS records to your domain registrar (GoDaddy, Cloudflare, Namecheap, etc.):

### 1. SPF (Sender Policy Framework) Record
*Authorizes Resend mail servers to send transactional emails on behalf of your domain.*
- **Type**: `TXT`
- **Host / Name**: `@` (or `nirai.in`)
- **Value**: `v=spf1 include:resend.com ~all`
- **TTL**: `3600` (or Auto)

### 2. DKIM (DomainKeys Identified Mail) Record
*Cryptographically signs outbound emails to verify sender authenticity and prevent spoofing.*
- **Type**: `TXT` or `CNAME` (Refer to Resend Dashboard > Domains)
- **Host / Name**: `resend._domainkey`
- **Value**: Unique public key string generated by Resend
- **TTL**: `3600` (or Auto)

### 3. DMARC (Domain-based Message Authentication) Record
*Specifies handling policies for unauthenticated mail and generates delivery health reports.*
- **Type**: `TXT`
- **Host / Name**: `_dmarc` (or `_dmarc.nirai.in`)
- **Value**: `v=DMARC1; p=none; rua=mailto:postmaster@nirai.in`
- **TTL**: `3600` (or Auto)

Once configured, verify status in Resend Dashboard under **Domains** until the status badge shows **Verified**.

## 4. Verification Checklist

Before opening the storefront to the public, verify:
- [ ] SPF record propagates (`dig TXT nirai.in` includes `include:resend.com`).
- [ ] DKIM record propagates (`dig CNAME resend._domainkey.nirai.in`).
- [ ] DMARC record returns `v=DMARC1; p=none; ...`.
- [ ] Resend domain status is **Verified** in Resend dashboard.
- [ ] Supabase Auth Custom SMTP is enabled and tested with a test registration.
- [ ] Test transactional email received in Gmail and checked: **SPF: PASS**, **DKIM: PASS**, **DMARC: PASS**.
